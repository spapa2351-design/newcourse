# 2026-07-28 — 운영 중 코스 편집 = 버저닝 (드래프트 → 퍼블리시) UI 설계

> 백엔드가 코스 버저닝으로 개발됨. 퍼블리싱된 코스를 다시 편집하면 현재 서비스 중인 버전은 그대로 두고
> 새 드래프트 버전이 생성되며, 퍼블리시해야 실서비스로 교체된다.
> 프로토타입에는 이 개념이 없었고(상태 4종 in-place 수정), 관리자 화면에 어떻게 녹일지 확정한 세션.

## 배경

기존 프로토타입은 `courseStatus` 하나로 `draft | saved | scheduled | published`만 관리하고, published 코스를
편집하면 **같은 객체를 in-place 수정**했다. 실서비스 보호 장치는 "종료된 회차 수정 불가" 부분 잠금뿐.
버전 생성·이전 버전 보관·미공개 상태 표시가 전부 없었다.

## 확정 결정

| # | 논점 | 결정 | 근거 |
|---|------|------|------|
| D1 | 버전 노출 수준 | **"공개본 / 작업본" 2트랙**. UI에는 항상 2개만 존재하는 것처럼 보이게 하고 v번호는 노출하지 않음. 버전 표기는 **반영 날짜**(`7.20 반영`) | 관리자가 원하는 건 ①지금 수강생이 보는 게 뭔지 ②내가 만진 게 아직 안 나갔다는 확신 ③되돌리기 3개뿐. git식 v1~vN 리스트는 인지부하만 늘고 "지금 뭐가 서비스 중인지"가 오히려 흐려짐 |
| D2 | 편집 진입 게이트 | 퍼블리싱된 코스는 **읽기 전용 상세 화면**으로 열리고 `[수정]` 버튼이 유일한 진입점. 예외 없음 | 게이트가 하나면 관리자가 외울 규칙이 없음. 텍스트/일정 구분해 진입점을 2개 두는 안은 탈락 |
| D3 | 드래프트 생성 시점 | `[수정]` 클릭이 아니라 **첫 저장**. 변경 없이 나가면 드래프트 자동 폐기 | 클릭만으로 버전이 생기면 구경만 한 것도 "수정 중"으로 남아 목록이 오염됨. 기존 `isDirty` 가드 재사용 |
| D4 | 반영 시점 2등급 | 진입은 하나지만 **저장 결과가 갈림**. 텍스트·이미지만 바뀌면 `즉시 반영`, 등록·출석에 영향 있는 항목이 바뀌면 `퍼블리시 필요` | 오타 하나 고치고 퍼블리시를 또 눌러야 하면 아무도 안 고침. 판단은 시스템이 하고 관리자는 진입 시점에 고민하지 않음 |
| D5 | 라벨 | **`임시저장`·`퍼블리싱` 기존 용어 유지**. "작업본 저장 / 변경사항 공개"는 폐기 | 임시저장은 "아직 확정 아님"이 단어에 이미 들어 있어 버저닝 모델과 그대로 맞고 익숙함. 신조어는 학습 비용 |
| D6 | 드래프트 존재 시 표기 | 버튼 라벨을 `[수정]` → **`[수정 중 이어서]`**로 바꾸고 `[수정 취소]`(폐기) 경로를 함께 노출 | 라벨이 그대로면 "또 누르면 새 버전 생기나?" 하고 멈춤. 폐기 경로가 없으면 잘못 만진 드래프트를 빠져나갈 길이 없음 |
| D7 | 빌더 내 상태 표시 | 우측 하단 초록 `퍼블리싱 완료` 바 → **앰버 `수정 중 — 아직 공개되지 않았습니다`** 바 + `[공개본 보기]`. `[수정 모드]` 버튼 삭제 | 그 초록 바의 두 역할(공개 중 고지 + 수정 모드 게이트)이 상세 화면으로 이동. 둘 다 두면 게이트 2개 |
| D8 | 퍼블리시 전 확인 | 퍼블리시 모달에 **변경 요약(diff) + 등록자 영향 3단 경고**(🔴 삭제 차수 등록자 / 🟠 수료조건 완화 / 🟡 일정 변경 재통보) | 드래프트 편집 중에도 공개본에 신규 등록자가 계속 쌓임. "8명 등록된 1차수가 삭제됩니다. 계속?" 한 줄이 사고의 대부분을 막음 |
| D9 | 과거 회차 | 종료된 회차는 **버전이 갈려도 불변**. 드래프트에서도 수정·삭제 불가 | 출결 기록이 붙어 있음. 기존 잠금 규칙 유지 |
| D10 | 종료 코스 | **상세로 열리되 `[수정]` 없음** — `🔒 종료 · 수정 불가` 칩, 반영 시점 배지 숨김. 목록 링크는 `?closed=1` | 출결·수료가 확정돼 버전을 새로 만들 이유가 없음. 그렇다고 목록에서 열 수 없게 하면 지난 운영 조건을 확인할 길이 사라짐 |

## 2등급 분류 (D4)

| 등급 | 항목 |
|------|------|
| **즉시 반영** | 코스 분류, 강사 소개, 코스 소개, 상세 주소, 오시는 길, 커버 이미지 |
| **퍼블리시 필요** | 코스명, 대표 강사, 교육 장소, 신청 기간, 등록 방식, 신청 권한, 차수 선택 방식, 취소·변경 정책, 수료 조건, 차수·회차 일정, 정원 |

경계 케이스 — **강사 변경**(소개글이 아니라 담당자 교체)은 수강생이 알아야 하므로 `퍼블리시 필요`.

## 화면 구성

### 읽기 전용 상세 (`admin/offline-detail.html`, 신규)

빌더와 같은 3분할(좌 요약 224px / 본문 800px / 우 차수 500px)이되 입력 컨트롤 없이 값만 텍스트로 표시.

- **헤더** — `🟢 공개 중 · 7.20 반영` 칩 + `[운영 현황]` `[수정]`. 드래프트가 있으면 `✏️ 수정 중 · 미공개 N건` 칩 추가, 버튼은 `[수정 취소]` `[수정 중 이어서]`로 교체
- **본문** — 3섹션(코스 기본 정보 / 모집·신청 설정 / 수료 조건). 각 행 우측에 `즉시 반영` / `퍼블리시 필요` 배지 + 상단 범례
- **우측** — 차수 카드(완료·진행중·예정 배지, 정원 초과 표시), 회차별 `🔒 종료` 잠금
- **모달 3종** — 수정 모드 전환 확인 / 미공개 변경 내역(from→to diff, 영향도 3단) / 드래프트 폐기

읽기 전용 화면에서는 **입력창처럼 보이는 요소를 쓰지 않는다**. 눌리지 않는 입력창은 버그로 오해된다.

### 빌더 (`admin/offline-builder.html`, 변경)

- 헤더 상태칩 2단 — `공개 중 · 7.20 반영`(클릭 시 상세로) + `수정 중 · 미공개`. 신규·임시저장 코스는 기존 단일 칩
- 우측 하단 앰버 바 + `[공개본 보기]`, `[수정 모드]`·`[수강관리]` 제거 (후자는 상세의 `[운영 현황]`과 중복)
- published 코스에서도 `[새 차수]`·퍼블리싱 버튼 노출 — 기존엔 published면 이 버튼들이 숨어 드래프트 편집 자체가 불가능
- 퍼블리싱 버튼 라벨은 드래프트 편집 중일 때만 `변경사항 퍼블리싱`

## 프로토타입 버그 2건 (버저닝 모델과 충돌)

| 증상 | 원인 | 처리 |
|------|------|------|
| 수정 모드 진입 시 공개본 상태가 임시저장으로 내려감 | `[수정 모드]` 버튼이 `setCourseStatus('saved')` | 버튼 제거. 편집 중에도 `published` 유지, 드래프트는 별도 플래그(`draftPending`)로 관리 |
| 임시저장 한 번에 종료 회차 잠금이 풀림 | 잠금 조건이 `courseStatus === 'published'`인데 `handleSaveDraft`가 `saved`로 강등 | 드래프트 편집 중에는 상태를 내리지 않음 |

## 검토했으나 채택 안 함

- **버전 히스토리 명시형** (CMS식 v1~vN 리스트 + 버전 셀렉터) — 감사 추적은 강하지만 관리자 인지부하 최대. 임의 시점 복원 니즈는 "직전 공개본으로 되돌리기" 1버튼 + 접힌 메뉴의 최근 3개로 흡수 가능
- **완전 은닉형** (저장 = 즉시 반영, 버저닝은 백엔드 안전장치로만) — 학습 비용은 0이지만 published 코스를 실수로 즉시 망가뜨림. 오프라인은 등록자·출석이 걸려 있어 위험
- **진입점 2개** (`[정보 수정]` 텍스트 전용 모달 / `[편집]` 풀 빌더) — 관리자가 진입 시점에 "이건 어느 쪽이지"를 판단해야 함. D4로 대체

## 백엔드 확인 필요 (UI가 갈림)

| # | 질문 | 영향 |
|---|------|------|
| Q1 | 작업본이 코스당 1개인가, N개 병렬인가 | **2트랙 모델의 전제.** N개면 D1이 깨지고 버전 리스트형으로 가야 함 |
| Q2 | 진행 중 수강생은 어느 버전을 보나 (등록 시점 버전 고정 vs 최신) | 수료 조건이 바뀌면 치명적. D8 경고 문구가 달라짐 |
| Q3 | 등록·출석 데이터가 버전에 묶이나. 차수·회차 ID가 버전 간 유지되나 | ID가 안 바뀌어야 diff를 "수정"으로 표현 가능. 안 그러면 전부 "삭제+추가"로만 보여 D8이 무력화 |
| Q4 | 롤백 시 등록자도 롤백되나 | 아니라면 "일정만 되돌아가고 등록자는 유지" 경고 필요 |

## 목록 → 상세 라우팅 (`offline-list.html`)

`courseEditHref(course)` 하나로 분기. 코스명 링크와 관리 열 연필 아이콘이 같은 목적지를 쓴다.

| 상태 | 목적지 | 이유 |
|------|--------|------|
| `active` / `published` | `offline-detail.html?courseId=N` (드래프트 보유 시 `&draft=1`) | 편집은 상세의 `[수정]`이 유일한 게이트 (D2) |
| `closed` | `offline-detail.html?courseId=N&closed=1` | 열람만 (D10) |
| `draft` / `saved` / `scheduled` | `offline-builder.html?courseId=N` | 아직 공개 전이라 in-place 수정이 맞음 |

목록 상태 열에는 `draftPending` 코스에 `● 수정 중` 앰버 배지를 상태 칩 아래 함께 표시.

## 프로토타입 버그 3건 (버저닝 모델과 충돌)

앞선 2건에 더해:

| 증상 | 원인 | 처리 |
|------|------|------|
| 아무것도 안 고치고 `[공개본 보기]`로 나가도 브라우저 이탈 경고 | `isDirty` 초기값이 무조건 `true` (빌더 진입 = 작업 중) | 편집 모드는 `!isEditMode`로 시작하고 마운트 시 초기값 주입은 변경으로 치지 않음. D3(변경 없이 나가면 조용히 폐기)과 정렬 |

## 미반영 (다음 작업)

- 퍼블리시 모달의 diff·영향 경고 (D8) — 현재 상세 화면 모달에만 있고 빌더 퍼블리싱 모달은 검증 체크리스트만
- 동시 편집 잠금 배너 ("박관리자가 12분 전부터 수정 중")
- 상세의 드래프트 diff는 더미 고정값 — 빌더에서 실제로 고친 내용이 반영되지 않음 (프로토타입 한계)
